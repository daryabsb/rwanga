# Rwanga IDE — Alive App Checklist (Phase 2)

> **This is the second chapter of the app's constitution.**
> Created: 2026-05-24 · Owner: Rwanga IDE · The launch checklist (`RWANGA_IDE_LAUNCH_CHECKLIST.md`) answers *"Can Rwanga launch?"* This document answers the question that comes after: *"Is Rwanga alive?"*

---

## 0. Entry Gate — when Phase 2 begins

> # ⛔ This checklist MUST NOT be used before the mechanical app is complete.
>
> # ⛔ No AI feature implementation may start before this phase is visually verified.

Phase 2 begins only when **every** entry-gate item below is TRUE. Until then, this document is dormant — do not pull items forward, do not improvise on them, do not let "we'll get there" reasoning leak Phase 2 work into Phase 1.

- [ ] Launch checklist P0 items are TRUE
- [ ] Settings UI is complete
- [ ] Settings are wired to real app behavior
- [ ] Visual E2E verification passed
- [ ] Flow remains continuous, never paginated
- [ ] Print Preview owns page truth
- [ ] Inspector / sidebar / panels obey responsive shell doctrine
- [ ] No new AI features started yet

When the gate is open, the next-action rule is: **pick one item — or one cluster of similar items — based on clarity or thematic similarity.** Do not run the chapters in order; run them by readiness.

---

## 1. App Identity / Soul

- [ ] Rwanga feels like a creative studio, not a code editor clone
- [ ] The UI has emotional warmth without harming focus
- [ ] Empty states feel intentional, not dead
- [ ] The script feels like a living project, not a flat file
- [ ] `.rga` is presented as the home of the script: script, notes, scenes, tags, timeline, references

## 2. Scene Weight

- [ ] Scene list gives each scene visual weight
- [ ] Scene cards show useful children: tags, notes, flags, cast, props, sound, location
- [ ] Tags belong inside / near the scene, not "on another planet"
- [ ] Scene state is visible: draft, reviewed, flagged, translated, production-ready
- [ ] Scene list gives a director immediate understanding of script complexity

## 3. Living Toolbar / Toolbox

- [ ] Toolbar is no longer dead / static
- [ ] Toolbar changes based on context: scene, action, dialogue, note, tag, sound, prop
- [ ] Important tools appear when needed, disappear when irrelevant
- [ ] Toolbar can become a side toolbox if that serves the writing space better
- [ ] Compact mode remains useful, not crippled

## 4. Hover Intelligence / "Sniffing Dog"

- [ ] Hovering meaningful objects reveals useful context
- [ ] Hover cards explain: this is a prop, sound, note, flag, character, location, etc.
- [ ] Hover cards show where else the object appears
- [ ] Hover cards are fast, calm, and non-annoying
- [ ] The app helps the writer discover meaning without opening panels

## 5. Script Object Awareness

- [ ] Characters feel like reusable story objects
- [ ] Props feel like reusable story objects
- [ ] Sounds feel like reusable story objects
- [ ] Locations feel like reusable story objects
- [ ] Notes / flags / reviews are anchored to exact script moments
- [ ] The user can understand object relationships without AI

## 6. Production Artifact Feeling

- [ ] Script export feels professional
- [ ] Synopsis export feels director-ready
- [ ] Scene summary export exists or is designed
- [ ] Breakdown-style export exists or is designed
- [ ] Exports feel like production documents, not plain printouts
- [ ] Rwanga output makes the project look valuable

## 7. Visual Comfort / Interior Design

- [ ] Panels have visual hierarchy
- [ ] Sidebar density is useful, not empty
- [ ] Inspector feels first-class
- [ ] Colors, spacing, shadows, borders, and cards create calm focus
- [ ] Light and dark themes both feel designed
- [ ] Kurdish / RTL visual comfort is checked, not assumed

## 8. Timeline Readiness Before AI

- [ ] Script timeline doctrine is saved
- [ ] Timeline is understood as cinematic time, not real time
- [ ] Text fragments can become addressable clips later
- [ ] Notes / reviews can point to exact timeline / script IDs later
- [ ] Timeline is not implemented until the app feels alive
- [ ] No AI feature depends on guessed text locations

## 9. Human Verification

- [ ] A writer can open the app and want to stay
- [ ] A director can understand the script structure visually
- [ ] A non-engineer can use the app without explanation
- [ ] The UI makes the script feel important
- [ ] The app produces emotional confidence, not just technical trust

---

## Exit — when Phase 2 closes

Phase 2 is complete when every checkbox above is TRUE *with visual evidence*, not "we think it works." Only then may AI feature implementation begin. This rule is binding the same way the launch P0 rule is binding: PARTIAL and UNKNOWN block exit exactly as hard as FALSE.
