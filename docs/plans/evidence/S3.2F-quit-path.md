## 1. The symptom (as recorded by S3.2)

Full e2e run 2026-07-27: **326 pass · 37 fail**, 1.2 h. Every sampled failure had the same
signature — the test body passed and then:

```
Test timeout of 60000ms exceeded while running "afterEach" hook.
   at app.close()
```

Each hang also leaked an Electron process tree (17 orphans found during S3.2; 16 more during this
slice).

## 2. Root cause A — the close guard has no human to answer it

Reproduced on `tests/integration/app-close.spec.js` test 1: **1.4 min**, `afterEach` timeout.

The chain:

| Where | What happens |
|---|---|
| `electron/main.js:99-117` | `mainWindow.on('close')` calls `event.preventDefault()` and sends `app.closeRequested` to the renderer. |
| `renderer/index.html:1577-1590` | Subscribes and calls `Rga.CloseGuard.confirmAppClose()`. |
| `renderer/js/close-guard.js:69-83` | Iterates **every** tab; for each dirty document awaits `Rga.Modal.showUnsaved(name)`. |
| `renderer/js/shell/modal.js:87-102` | Shows `#unsaved-modal` and returns a Promise that resolves **only on a button click**. |
| `electron/main.js:107-116` | After `CLOSE_RESPONSE_TIMEOUT_MS` with no verdict, the close is **aborted** — by design, never force-quit over unsaved work. |

Under automation nobody clicks, so the promise never settles, the verdict never arrives, and
Playwright's `app.close()` never resolves.

**Verdict: test hygiene, not a product defect.** The guard is correct for a real user, and
`app-close.spec.js` test 2 proves it — it answers the modal with Discard and the app quits in 2.7 s.
A diagnostic probe confirmed the live behaviour directly: with a dirty document, 16 s after
`window.rwanga.window.close()` the modal is still on screen and the window is still open — exactly
what a user waiting at a prompt should see.

**Fix:** one shared helper, `rwanga-editor/tests/helpers/app-teardown.js`:

- `closeApp(app)` — marks every open document clean (all tabs, not just the active one, because the
  guard iterates them all), tidies a modal the test body left open, then closes.
- It generalises the idiom the repo already used in
  `tests/e2e/filmustageation/print-contract.spec.js` (`clearDirtyAndClose`); that local wrapper was
  deleted so there is one helper, not two.
- Teardown asserts nothing and weakens nothing. Specs that *prove* the guard keep their assertions:
  `app-close.spec.js:65` (`app.waitForEvent('close')` around a user-driven Discard-quit) was
  deliberately left untouched.

Swept across **60 spec files / 124 teardown call sites** under `tests/e2e/**` and
`tests/integration/**`.

`app-close.spec.js`: **1.4 min hang → 2/2 pass in 7.9 s.**

## 3. Root cause B — the force-kill specs leaked their process tree

`autosave.spec.js` and `recovery.spec.js` simulate a crash with `proc.kill('SIGKILL')` on the
Electron **main** process. On Windows the GPU / renderer / utility children survive that kill and
keep the pipe Playwright talks to open, so Playwright never observes the app dying. Consequences:

1. the dead `ElectronApplication` handle is disposed at **worker** teardown instead, blocking the
   full 60 s (`Worker teardown timeout of 60000ms exceeded` — an error attributed to no single test,
   which is why S3.2's sampling never caught it); and
2. the surviving children become the orphaned Electron processes both S3.2 and this slice had to
   clear by hand.

Two earlier hypotheses were tried and rejected before this one (an immediate `a.close()`, then a
bounded `close()` race) — both left the worker teardown hanging, which is what pointed at the pipe
being held open by *someone else*.

**Fix:** `killApp(app)` in the same shared helper kills the process **tree**
(`taskkill /pid <pid> /T /F` on win32, `SIGKILL` elsewhere), waits for exit, then disposes the
Playwright handle so worker teardown has nothing left to close. Both specs now use it.

`autosave.spec.js`: **1.3 min (with a worker-teardown error) → 3/3 pass in 13.3 s.**
`autosave` + `recovery` together: **6/6 pass in 33.1 s.**

## 4. Files changed

- `rwanga-editor/tests/helpers/app-teardown.js` — new; `closeApp` + `killApp`.
- 60 spec files under `rwanga-editor/tests/e2e/**` and `rwanga-editor/tests/integration/**` — teardown

## 5. A regression the sweep itself introduced — caught and fixed

The first post-fix full run surfaced **8 failures reading `ReferenceError: closeApp is not defined`**
in `tests/e2e/filmustageation/tag-plugin-ownership.spec.js`: the sweep had appended the `require`
at the **bottom** of that file (inside a function body), not in its top require block. Fixed by
moving the require next to the other requires; a placement check now covers every converted file
(require line number must precede the first `closeApp(` call — 60/60 pass). This is recorded rather
than quietly corrected: the first measurement of a new baseline is exactly where such a mistake has
to be caught.
