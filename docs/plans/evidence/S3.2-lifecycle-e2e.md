## The Step-1 seam (dialog-free save/open)

Native dialogs cannot be driven by Playwright. The plan's skeleton proposed assigning
`doc.handle` from the renderer; **a better seam already exists in the repo** and was chosen instead:
stub `dialog.showSaveDialog` / `dialog.showOpenDialog` in the **main process** via
`app.evaluate(({ dialog }) => …)` — the idiom of `tests/integration/atomic-save.spec.js`.

Why it is stronger: the real user path runs end to end —
`FileManager.saveAs()` → IPC `files.pickSaveAs` → `writeFileAtomic` (+ `.bak`) → `Doc.rebindHandle`
→ `Doc.clearDirty`, and `FileManager.openFromDialog()` → IPC `files.pickOpen` → `Doc.deserialize`.
The `doc.handle = p` shortcut would have skipped `origin` and `displayName` rebinding entirely — the
very things PF-05 must prove.

Gotcha recorded in each spec: `FileManager.save()` reads the **module-local** `activeDoc` (set by
TabManager on tab activation, `tab-manager.js:148`), not `getActive()` — so every spec waits on
`FileManager.getActive()` before acting.

## Step 4 — full e2e regression: what it actually showed

`npm run test:e2e` (whole suite, 1.2 h): **326 passed · 37 failed.** The three new specs are **not**
among the failures — they pass inside the full run.

**"No new failures vs before this slice" could not be answered by comparison: no e2e baseline has
ever been recorded.** The campaign's baseline truth (`1936 · 30 fail · 1 skip`) is the **unit** suite
only; no evidence file or checkpoint records an e2e pass/fail count. So the question was answered by
**measurement** instead:

1. **Isolation run** — `autosave.spec.js` + `recovery.spec.js` + `paper-view.spec.js` run **alone**
   (this slice's specs not loaded at all): **7 failed · 6 passed.** Identical failures. Since the new
   files are not even in that run, those failures cannot originate from this slice.
2. **Clean-environment run** — after killing 17 orphaned Electron processes:
   `tests/e2e/lifecycle` + `recovery.spec.js` → lifecycle **3/3 PASS**, recovery **2 failed** with the
   same signature. So the failures are not environment saturation either.

### The signature (→ GAP-3-3)

Every sampled failure is **`Test timeout of 60000ms exceeded while running "afterEach" hook`** at
`app.close()`. **The test bodies pass; the app will not quit.** Consequence: each hung close leaves
orphaned Electron processes behind (17 were found and cleared during this slice).

Working hypothesis (unproven, for the fix-slice): specs that leave the document **dirty** hit the
unsaved-changes prompt on quit, which blocks `app.close()` under automation. Consistent with the
evidence — `print-contract.spec.js` (`clearDirtyAndClose`) and the three new lifecycle specs, which
all clear dirty before closing, pass; `app-close.spec.js` ("closing with unsaved changes prompts") is
itself among the failures.

This is **not** a lifecycle defect in the features under test (recovery, autosave, paper view all
assert green before teardown), and it is out of S3.2's frozen scope → recorded as **GAP-3-3** with a
future owning fix-slice. It matters for the QG-12 roll-up: the e2e suite cannot be called green, and
**an e2e baseline should be recorded** the way S0.1 recorded the unit baseline.
