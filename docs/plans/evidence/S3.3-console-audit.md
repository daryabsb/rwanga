## Flows walked

`page.on('console')` and `page.on('pageerror')` were subscribed for the whole session, from launch
to close:

1. **launch** — cold boot of the real app.
2. **new-script** — `FileManager.newScript()`.
3. **typing-block-types** — the real key flow through the locked script framework: slug → Enter →
   action → Enter → Tab (character) → Enter (dialogue) → Tab (shot) → a second slug → action.
4. **save-as** — the real path, native dialog stubbed in the main process
   (`saveAs()` → IPC → atomic write → rebind → clearDirty).
5. **reopen** — `openFromDialog()` reading the bytes back off disk.
6. **print-preview** — open, settle, hide.
7. **page-setup** — paper size → A4, orientation → landscape → portrait, paper size → Letter.
8. **undo-redo** — type, then Ctrl+Z ×5 and Ctrl+Y ×5.

## What the warnings mean (and what escalates)

Most of these are **benign layering**: the same command registered first by the menu and then by the
keyboard-settings applicator (#2, #4, #5, #7, #8), or a scoped surface deliberately taking over a key
while it is open (#3, #12 — Esc). Last-wins is the registry's documented behaviour and the winner is
the intended owner.

**Three are genuine collisions between different features, and one of them is a shipped defect** —
escalated as **GAP-3-5** (§0.2: escalate, don't paper over; not fixed here because S3.3's scope froze
when it opened):

- **`Ctrl+Shift+S` — Save As is dead on arrival.** `settings-registry.js:549` gives `kb.saveAs` the
  default `Ctrl+Shift+S`, and `:585` gives `kb.sceneNavigator` the **same** default. Scene Navigator
  registers last and wins, so out of the box **Ctrl+Shift+S opens the Scene Navigator and Save As has
  no working shortcut** — while the Settings screen still displays `Ctrl+Shift+S` next to "Save As".
  That is a Settings-honesty violation as well as a lost shortcut.
- **`Ctrl+Shift+E`** — the shell's scriptWorkspace panel toggle is overridden by Export PDF.
- **`Ctrl+Shift+F`** — the search panel toggle is overridden by a legacy-shim registration.

The **CSP warning** is Electron's standard development-mode notice (it is not shown in a packaged
build) but it does describe the real renderer configuration; noted in GAP-3-5 as a hardening item to
settle before launch, not a console-cleanliness failure.
