## Notes / deviations from the plan's predicted totals

1. **Class B = 0, not 3.** The plan pre-classified the parenthetical trio (#26–28) as a deliberate
   cosmetic deferral to quarantine in S1.3. The evidence contradicts that: the cosmetic fix
   *already shipped* (Density Slice 6 — see the in-CSS comment at editor-prosemirror.css:2493-2498),
   and the tests are red only because the R1 logical-property migration (`padding-left` →
   `padding-inline-start`, per RTL_SCREENPLAY_CONVENTION) broke the test's `declIn()` extraction
   regex. They are one shared helper fix, executed in S1.2. **S1.3 therefore becomes a verification
   no-op** (nothing to quarantine); it closes by recording this fact, not by skipping tests that can
   be green today.
2. **Class C sub-verdict = (i) stale, both.** `editor-recovery-phase3.test.js` covers "editor
   recovery" in the UX sense (Flow gutter + Draft footer), NOT crash/autosave recovery — commit
   `9693012d` (recovery-prompt) is unrelated. Both reds are re-points against the locked F1 Flow-rail
   design; S1.4 executes them.
3. **Class D = 1 (GAP-1-1).** `source-audit.test.js` "audit (b)" is a standing constitution guard,
   not a stale snapshot — and it caught a real (low-severity) violation introduced by H6
   (`0b024e24`): `settings-workspace.js:522` reads `classList.contains('is-disabled')` as state
   truth. Fix direction: read `entry.requiresPro` (already in closure; same file uses the correct
   idiom at 584/588). Per doctrine rule 6 this is a gap row + fix-slice, never a re-point.
