# S2.3F — GAP-2-1 fix: New doc paints at full page size in Flow

Date: 2026-07-29
HEAD SHA at slice start: `99301c22382bf262d566be4ea2a67346f08d3548`

## Symptom (user-reported, re-raised 2026-07-29)

Opening a New document in Flow view showed a short page — a large dead band relative to a full sheet
of paper — that only grew toward its correct height as content was typed in.

## Step 1 — reproduce and measure

Ad-hoc Playwright/Electron script (`repro-tmp.js`, not committed) against a stock New doc
(Letter, `FileManager.newScript()`), Flow view:

| Moment | `#editor` height (px) | Notes |
|---|---|---|
| First paint, empty New doc | **227.59px** | Configured Letter paper height is 11in = **1056px** at 96px/in. 227.59px is **21.5%** of the paper height. |
| After typing 2 short lines | **261.19px** | Height increased by 33.6px purely from 2 lines of text — confirms "grows as you type." |

Width was correct throughout (816px = 8.5in × 96), confirming the defect is height-only, consistent
with the CSS split found in Step 2 (width and height are set by different rules).

## Step 2 — root cause

`rwanga-editor/renderer/css/editor-prosemirror.css:52-54` (pre-fix):

```css
#editor-container.view-flow #editor {
  ...
  width: var(--page-width);
  min-height: auto;
  height: auto;
  ...
}
```

This was a deliberate Fork A ("Brick 4+5") decision — the comment at the top of the rule reads *"no
geometry, no growth model, no paper shell (Fork A invariants intact)"*. It made `#editor`'s height
purely CONTENT-driven: an empty/near-empty document has almost no content, so it renders only as tall
as its one empty paragraph + padding.

Compounding this, `rwanga-editor/renderer/js/editor/page-surface.js` (pre-fix) only ever published a
`--page-width` CSS custom property — there was no `--page-height` token anywhere in the app for a
height rule to consume even if one existed.

**Proof, not assumption:** the diagnosis was confirmed by reverting the fix (`git stash` on the three
touched files) and re-running the new regression spec — all 4 tests reproduce the exact pre-fix
heights (227.59px / 233.27px / 227.59px / 233.27px for the four Letter/A4 × LTR/RTL combinations),
then pass cleanly once the fix is restored.

## Step 3 — the fix (TDD: failing test first, then green)

**Test first:** `rwanga-editor/tests/e2e/flow/new-doc-page-geometry.spec.js` was written and
confirmed RED against the pre-fix code (4/4 failing, each reporting the exact pre-fix height above
against the expected full paper height).

**Fix, in two files:**

1. `rwanga-editor/renderer/js/editor/page-surface.js` — `apply(pageSetup)` now also publishes
   `--page-height` (alongside the existing `--page-width`) from the resolved layout profile's
   `pageSize.h`.
2. `rwanga-editor/renderer/css/tokens.css` — added a default `--page-height: 11in` (mirrors the
   existing `--page-width: 8.5in` default), covering the first-paint gap before
   `Rga.PageSurface.apply()` runs.
3. `rwanga-editor/renderer/css/editor-prosemirror.css:52-59` — `#editor-container.view-flow #editor`
   now uses `min-height: var(--page-height)` (a FLOOR) with `height: auto` unchanged (so the page
   still grows past one page's height once content overflows it — this is not a height cap).

**Doctrine check (Flow continuous-drafting surface, locked 2026-05-23):** the fix changes only the
MINIMUM height of the single `#editor` element. No page seams, capsules, masks, or per-page chrome
were introduced; `#editor` is still exactly one continuous DOM element (confirmed by the existing
doctrine test `flow-page-presence.spec.js` — "Flow stays continuous: one page element, no sheet
stack (Law 4)" — still green, unmodified). Fork A's actual invariant ("no page-break chrome, no
paginated growth model") is intact; only the floor a blank page starts at changed.

## Gaps opened (not fixed here — out of GAP-2-1's scope)

- **GAP-2-3** — Page Setup's paper-size switch (Ctrl+Shift+G → select a size → Apply) silently does
  nothing, for every user, always. `page-setup-dialog.js`'s Apply handler writes
  `Store.set('pageSetup.paperSize', paper.value)` where `paper.value` is `'Letter'|'A4'|'Legal'`
  (from `Constants.PAPER_SIZES` keys, `page-setup-dialog.js:31`), but the settings-registry entry only
  accepts lowercase `['letter','a4','custom']` (`settings-registry.js:283-291`); the case-sensitive
  `select` validator (`settings-validators.js:27-30`) rejects every call, silently (`console.warn`,
  no exception, no UI feedback). Confirmed by direct reproduction (debug script): selecting A4 and
  clicking Apply leaves `doc.settings.pageSetup.paperSize === 'Letter'` and
  `Store.effective('pageSetup.paperSize') === 'Letter'`.
- **GAP-2-4** — `tests/unit/shell/editor-page-color.test.js`'s "colour-only" guard test asserts the
  pre-fix `min-height: auto` invariant this slice supersedes. Needs a ruling on updating the guard
  (there is direct precedent in the SAME test: its `box-shadow: none` guard was already replaced once,
  when the F2 shadow slice shipped).
